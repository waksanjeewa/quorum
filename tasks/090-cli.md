## Journal
- [claude-opus-4-8] CLI in packages/cli/ (95 tests, 4 CLI integration tests vs a live daemon). Binary verified: `node dist/index.js` prints help; `status` with no daemon gives a friendly "start one with…" message. Commands: start / status / inject / pause / resume / stop / attach. client.ts reads .quorum/daemon.json for {url,token}; commands.ts has testable functions (statusOf/inject/control/streamEvents/latestSessionId) that target the latest session by default; format.ts renders seat-colored one-line events.
  - DESIGN NOTE (start model): `quorum start` runs the daemon IN-PROCESS in the foreground (hosts QuorumHttpServer + creates the session + subscribes to print the transcript), rather than spawning a detached background daemon. Ctrl+C on `start` = kill switch (stops the session, closes server). This is the v0.1 shape; a true detached daemon (so start returns and other terminals attach) is a follow-up. The acceptance's "Ctrl+C on attach never kills the session" is satisfied by the SEPARATE `attach` command (SSE reader; Ctrl+C aborts only the stream). `quorum stop` always stops.
  - streamEvents parses SSE frames from GET /events?token= (EventSource-style, token via query since headers can't be set on it). Works with Node's fetch streaming body.
